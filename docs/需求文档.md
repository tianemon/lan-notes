# 局域网笔记 — 需求文档

## 1. 项目背景

个人开发者平时会在手机上随手记笔记，但想把笔记发到电脑上继续编辑时，往往要经过网盘、聊天工具、数据线等繁琐流程。本项目提供一个**纯局域网内同步**的跨平台笔记应用：手机和电脑处于同一 WiFi/局域网时，笔记自动或手动同步，不依赖任何公网服务器。

## 2. 目标用户与使用场景

- **目标用户**：个人开发者（单人使用，多台设备：手机 + 电脑）
- **典型场景**：
  1. 手机上新建/编辑笔记 → 回到电脑前打开应用 → 笔记已同步，继续编辑
  2. 电脑上整理笔记 → 手机上随时查看

## 3. 功能需求

### 3.1 笔记基础功能

| 编号 | 功能 | 描述 | 验收标准 |
|------|------|------|----------|
| F1 | 新建笔记 | 列表页点击「+」新建，进入编辑页 | 可创建空笔记并保存 |
| F2 | 编辑笔记 | 编辑标题和正文，内容变更后自动保存（防抖 1s） | 修改内容后无需手动保存，退出重进内容保留 |
| F3 | 删除笔记（回收站） | 列表项删除后进入回收站（内容保留），可恢复；清空后物理删除不可恢复 | 删除后列表移除；回收站可看到并恢复；清空后重启不恢复 |
| F4 | 笔记列表展示 | 按最近更新时间倒序，显示标题、正文摘要、更新时间 | 列表排序正确，摘要截断合理 |
| F5 | 搜索笔记 | 按标题和正文关键字实时过滤 | 输入关键字即过滤，支持清除 |
| F6 | 本地数据持久化 | SQLite 本地存储（drift） | 重启应用数据不丢失 |

### 3.2 局域网同步功能

| 编号 | 功能 | 描述 | 验收标准 |
|------|------|------|----------|
| F7 | 局域网设备自动发现 | 基于 mDNS：开启同步的主机广播服务，其他设备自动发现 | 同一局域网内设备无需输入 IP 即可互相发现 |
| F8 | 手动同步笔记 | 同步页提供「立即同步」按钮，触发全量增量合并 | 点击后双向数据一致 |
| F9 | 自动同步笔记 | 设备连接建立后，任一方增删改笔记自动推送到对端 | 无手动操作下两台设备数据保持一致 |
| F10 | 同步冲突处理 | 同一笔记被多端修改时按「版本号 + 最后写入时间」合并（LWW） | 冲突后两端数据最终一致，不丢失任何一端的较新修改 |
| F11 | 同步状态显示 | 显示连接状态、已连接设备、最近同步时间、同步中指示 | 用户能明确感知当前同步是否正常 |
| F12 | 多设备连接管理 | 主机端显示已连接设备列表并支持断开；客户端显示当前连接目标 | 多台设备可同时连接主机，连接关系清晰可管理 |

### 3.3 同步拓扑设计（v2：P2P 对等模式）

采用**对等（P2P）模式**，每台设备完全平等，两两直连：

- **每台设备**同时运行 WebSocket 服务端（固定端口）+ 客户端角色
- 打开同步开关后：自动发现同一 WiFi 下的其他设备，自动连接（连接去重规则：设备 ID 字典序小者主动发起连接）
- 任一设备笔记增删改 → 立即推送给所有已连接设备（广播）
- 设备重启/IP 变化 → 重新发现自动重连，无需手动操作

| F13 | 设备身份与设备名 | 每台设备有持久化设备 ID + 可修改的设备名，身份不随 IP 变化 | 重启后设备 ID 不变；改名后列表显示新名字，已配对关系保留 |
| F14 | 配对请求确认 | 首次连接：手动点击目标设备发起配对请求，对端弹窗点「同意」才配对成功；配对时交换 HMAC 密钥，后续连接挑战认证防伪装 | 未配对无法连接；对端拒绝则不建立；伪造 deviceId 无密钥过不了挑战 |
| F15 | 信任列表自动连接 | 配对成功后双方互相信任，后续自动连接、无需再输密码；IP 变化不影响重连 | 配对的设备重启/换 IP 后自动重连并同步 |
| F16 | P2P 多向同步 | 任一设备增删改笔记，所有已连接设备实时收到 | 3 台设备互连时，任一端修改其余两端秒级同步 |
| F18 | 智能扫描与直连（v4） | 常态不扫描（已连接靠连接通信）；未配对不主动扫描，仅手动「重新扫描」；已配对断线退避扫描（5s→10s→…→60s 封顶）；打开 App 先直连缓存地址（3 次），失败再扫描；不保活，亮屏/回前台自动恢复 | 息屏断联可接受；亮屏打开 App 秒级恢复同步；未配对设备不打扰 |

### 3.4 认证与设备信任（v2 新增）

**首次连接必须认证，后续自动连接**：

- **设备身份**：每台设备首次启动生成持久化设备 ID（UUID，存本地），设备名可修改；身份不依赖 IP（IP 变化不影响识别与重连）
- **设备密码**：每台设备在设置中设置自己的连接密码（可修改）；对方首次连接需输入本机密码
- **信任列表**：密码验证通过后，双方将对方设备 ID 记入本地信任列表（含设备名、首次配对时间）；后续连接凭信任列表直接放行，无需重复输密码
- **改密码**：已配对设备不受影响（信任关系已建立）；新设备需用新密码配对
- 密码仅在首次配对时传输验证（局域网内），验证成功后长期信任
- **设备 ID 冲突防护（task-14 补充）**：对端 deviceId 与本机相同时拒绝连接并断开
  （握手/会话登记时），UI 提示「设备 ID 冲突：检测到与本机相同的设备 ID（可能恢复
  了备份数据），请在设置中重置设备 ID」；发现列表出现同 ID 设备不自动连接并报警，
  与信任列表相同 deviceId 但不同 IP 属正常（IP 变化）不误报；设置提供「重置设备
  ID」入口（重新生成 deviceId + 清空信任列表，旧配对失效需重新配对）

## 4. 非功能需求

| 类别 | 要求 |
|------|------|
| 跨平台 | 一套代码覆盖 iOS / Android / Windows / macOS |
| 成本 | 免费开源方案，无云服务、无服务器费用 |
| 部署 | 纯本地运行，数据只存在于局域网内设备 |
| 隐私 | 笔记不出局域网，不经过任何第三方服务器 |
| UI 风格 | flat（扁平）风格，Material 3 |
| 单机可用 | 无网络/未开启同步时，本地笔记功能完全可用（离线优先） |

## 5. 整体验收标准

1. 四端（iOS/Android/Windows/macOS）共用一套 Flutter 代码，本机（Windows）至少验证 Windows 桌面端 + Android 端编译通过、功能可用
2. 两台设备处于同一局域网：开启主机后，客户端自动发现并连接
3. 连接后任一端新建/编辑/删除笔记，另一端 2 秒内自动同步
4. 断网重连后数据自动对齐，无丢失
5. 应用重启后所有笔记保留

# 需求变更记录（task-31：同步页重构 + 互联手动化）

## 背景
用户发现下线检测「一杀后台立马离线」——符合预期（5s 会话层心跳 + 不重连）。本轮聚焦同步页 UI 与互联机制的简化。

## 需求清单（用户确认版）

### R1 同步开关容器（需求1+2合并）
- 一个容器：首行「同步」+ 丝滑滑动开关（开启/关闭）
- 开启后：容器展开，下方显示两行文案：
  ```
  已开启WebSocket服务端，端口58888
  已连接n台设备
  ```
- 关闭后：容器缩小成一行（只有「同步」+ 开关）

### R2 已配对设备列表
- 断开后状态直接显示「已断开」（不再显示「自动连接中」）
- 设备行只显示设备名，ID 仅供程序内部使用（不展示）

### R3 设备连接开关模型（用户确认）
- 每设备行两个 Switch，垂直排列，自动连接在下
- 自动连接开关：开=上线自动连；关=不自动连 + 拒绝对方连接
- 手动连接开关：控制当前连接；连接后自动打开；手动关=断开；手动开=重连
- 联动：自动开+手动关 → 下次启动自动打开并连接；自动关 → 手动开关下次启动默认关
- 被拒逻辑：在线方对某设备 autoConnect=false 时拒绝该设备连接；被拒方自动关闭对该在线方的自动连接开关（持久化）
- 取消配对：保持现状

### R4 连接状态持久化（JSON）
- autoConnect 持久化（TrustedDevices 列）
- 被拒后自动关闭的 autoConnect 写库持久化，重启后保持

### R5 发现设备区（需求6 + Q3）
- 两个按钮：「可被发现」「扫描设备」
  - 可被发现：向外广播 30 秒（每 5 秒一次），30 秒后自动停止
  - 扫描设备：持续监听 30 秒，然后自动停止
- 开启同步不再持续广播——只打开 WebSocket 服务端等待已连过的设备连入（凭缓存直连）
- 设备互联只保留手动开关（场景少，基本自己的设备，手动最稳妥）

### R6 整体 UI 优化
- 组件美观统一（GlassCard 风格）
- 滑动开关丝滑、精致（不胖）
- 列表按钮 hover 覆盖完整，不留背景容器直角（取消配对按钮）

## 架构影响
- enable 后不再 publish（不持续广播）；广播/扫描改为手动临时触发
- 删除退避扫描（直连失败不自动扫描，等对方上线连本机）
- 新增协议消息 auto_connect_rejected（Q4 拒绝通知）
- 传输层心跳已收编会话层（上一轮重构，5s）
